## 🌍 Deploy online (real-time across devices)

The app is a standard Node/Express app that persists to a JSON file. To let
many devices sync live, deploy it to any Node host. **Render (blueprint included)** is the easiest:

### One-click on Render (free)
1. Put these files in a GitHub repo (or use the included `render.yaml`).
2. On [render.com](https://render.com) → **New → Blueprint** → select the repo.
3. Render auto-detects `render.yaml` and deploys with `node server.js`.
4. Open your deployed URL on multiple devices.

Or on **Railway**: new project → Deploy from repo → it auto-runs `npm start`.
On **Glitch**: upload the folder → it runs automatically and gives a shareable URL.

> **Multi-device sync:** every user opens the same deployed URL. Updates are
> pushed live over Socket.IO — when a secretary submits, connected pastors/admins
> see it instantly.

> **Data note:** the app stores data in `data/db.json`. On free hosts the
> filesystem is often ephemeral, so reports reset on redeploy. For durable
> storage attach a persistent disk (Render) or switch `DATA_FILE` to a shared
> database later.

## 🤖 Generative AI Analytics (optional, free)

Insights are generated by a real LLM when a key is configured; otherwise the
built-in engine is used, so the app always works.

### Two ways to enable it
1. **In the app (easiest):** log in as **Admin → AI Analytics → AI Settings**, paste
a free key, and click **Save & Apply**. No code or env vars needed.
2. **Environment variable:** set `LLM_API_KEY` (optionally `LLM_BASE_URL` and `LLM_MODEL`)
on your host.

Any **OpenAI-compatible** key works. Free, no credit-card options:
- **Groq** — [console.groq.com](https://console.groq.com) (fast Llama models, e.g. `llama-3.1-8b-instant`)
- **Google Gemini** — [aistudio.google.com](https://aistudio.google.com) (e.g. `gemini-2.0-flash`)
- **OpenRouter** — [openrouter.ai](https://openrouter.ai)

Defaults when nothing is set: base URL `https://api.openai.com/v1`, model `gpt-4o-mini`.

## ⚠️ Data notes
- Data is stored in `data/db.json` and created automatically on first run.
- For true multi‑machine persistence, point `data/` to a persistent volume
  (or a shared database) on your host.
- The demo data file ships empty so the app seeds the 6 branches, the admin,
  and auto‑generated pastor logins on first launch.
